# HARD REQUIREMENTS

1. **Python only. Streamlit UI.** The application must run via `streamlit run app.py` as the sole entry point.
2. **Inputs (required in project root):**
   - `player_health_data.json` containing the roster of players, historical training loads (ACWR - Acute-Chronic Workload Ratio), GPS tracking data, sleep scores, wellness survey scores (fatigue, soreness, stress, mood), and injury history.
   - `credentials.json` containing the Groq API key under the key `"groq_api_key"` (REQUIRED for the LLM RAG protocol briefing engine). Example: `{"groq_api_key": "gsk_..."}`. Never hard-code, print, or log the key.
   - `medical-protocol.md` and `briefing-template.md` (see section 6).
   - If any core input file is missing, or `credentials.json` has no valid `groq_api_key`, show a clean styled error message using `st.error()` naming exactly what is missing, and stop execution.
3. **Core Architecture & Components:**
   - **Predictive Model (Injury Risk Classification):** A trained machine learning model (e.g., Logistic Regression, Random Forest, or Gradient Boosting built with `scikit-learn`) evaluating player telemetry (ACWR, sleep duration, wellness ratings) to output a binary classification (`Low Risk` / `High Risk`) and an exact probability score (e.g., 0.84 injury risk). Must include a model performance dashboard tab showing accuracy, precision, recall, confusion matrix, and cost-of-error analysis (false positives vs. false negatives).
   - **LLM RAG Component (Protocol-Grounded Briefings):** An LLM agent powered by Groq (`llama-3.3-70b-versatile` as primary, `llama-3.1-8b-instant` as backup) that reads `medical-protocol.md` fresh on every run and generates a structured, clinical briefing and load-management recommendation for high/borderline risk players.
   - **Human Checkpoint (Medical Team Sign-Off):** No player is cleared to play or benched without explicit sign-off from the club doctor or lead physiotherapist. The UI includes an interactive sign-off workflow where medical staff can review the AI risk score and RAG briefing, then approve clearance, modify training restriction, or mandate rest.
   - **Groq Free-Tier Rate Limit Handling:** Send requests efficiently, implement exponential backoff (2s, 4s, 8s) on HTTP 429 errors, and show clean status loaders. Cache results in `st.session_state`.
4. **Executive Dashboard & UI/UX:**
   - **Metrics Overview (KPI Cards):** Total Active Roster, Low Risk Players, High Risk / Flagged Players, Pending Medical Sign-Offs, and Protocol Adherence Rate.
   - **Player Health Tracking Table:** A clean tabular grid showing player name, position, ACWR, sleep score, wellness score, ML Risk Classification, Probability Score, Medical Sign-Off Status, and Actionable Protocol Summary.
   - **Model Performance & Business Case Tab:** Displays evaluation metrics (Precision/Recall, ROC-AUC), error cost analysis (cost of a missed injury vs. cost of a false alarm), and a 3-year TCO / buy-vs-build business assessment.
5. **Markdown Rule Files (The Protocol & Templates):**
   - `medical-protocol.md`: Defines club thresholds for ACWR safety zones, sleep debt limits, wellness score red flags, and mandatory rest protocols. Injected into the LLM system prompt.
   - `briefing-template.md`: Defines the clinical structure for the AI-generated coach and medical team briefing.

## PLAYER HEALTH TRACKING TABLE: DATA MODEL & RENDERING RULES (CRITICAL)

The tracking tab must display every player record in a proper rows-and-columns grid. Raw JSON, Python lists/dicts, or text dumps are NOT acceptable.

**A. Flatten the data before rendering**

- Build a single flat `pandas.DataFrame` combining player vitals, predictive model outputs, and LLM briefing summaries.
- Use ONE ROW PER PLAYER. Expected row count = total number of players in the roster (e.g., 30 squad members). Display this count above the table.
- Exact columns, in this order:
  1. `Player ID` (DM Mono)
  2. `Player Name`
  3. `Position`
  4. `ACWR (Workload Ratio)` (Numeric, colored conditional on safety range 0.8 - 1.3)
  5. `Avg Sleep (Hrs)` (Numeric)
  6. `Wellness Score (1-10)` (Numeric)
  7. `ML Risk Class` (`Low Risk` / `High Risk`)
  8. `Risk Probability` (Percentage format)
  9. `Medical Status` (`Pending Review`, `Cleared`, `Rest Mandated`, `Modified Training`)
  10. `Protocol Rationale` (One-sentence clinical justification)
  11. `Decided By` (`ML Model + LLM RAG` / `Fallback Rule`)

**B. Render with Streamlit's Native Data Grid**

- Use `st.dataframe(df, use_container_width=True, hide_index=True, height=500)` with `st.column_config`.
- Apply pandas `Styler` (`df.style.map(...)`) and leading emojis for status visibility: 🟢 `Low Risk`, 🔴 `High Risk`, 🟡 `Pending Review`, 🔵 `Cleared`.

**C. Search and Filters**

- Text search across Player Name and Position.
- Multi-select filters for Position, ML Risk Class, and Medical Status.
- CSV download button (`st.download_button`) for exporting filtered player health reports.

## PIPELINE & WORKFLOW

1. **Startup & Initialization:** Validate inputs (`player_health_data.json`, `credentials.json`, markdown protocols). Load or train the baseline scikit-learn predictive model.
2. **Execution Trigger:** Sidebar button: **"Run Health & Injury Risk Audit"**.
3. **Pipeline Steps:**
   - Run telemetry through the predictive model to calculate risk probabilities.
   - For high-risk or borderline players, query the Groq LLM agent with player telemetry and `medical-protocol.md` to generate clinical briefings.
   - Render results in session state and update the dashboard KPIs and tracking grid.
